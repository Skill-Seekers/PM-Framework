# Meridian: a worked example

Meridian-1 is a **fictional** AI accelerator program for a fictional customer. Every person, company, number and date is made up. Nothing here comes from a real program.

It exists to show the framework working end to end: a real workspace, a real Sev 1 taken through every issue state, and every artifact the tool produces along the way.

| Look at | What it is |
|---|---|
| [walkthrough/SEV1_WALKTHROUGH.md](walkthrough/SEV1_WALKTHROUGH.md) | Start here. The Sev 1 from detection to retrospective, command by command, with each refusal and the guard that caused it |
| [workspace/](workspace/) | The program as it stands on 2026-07-03: registers, decision records, the brief, the weekly drafts and RAID snapshots |
| [workspace/reports/](workspace/reports/) | Three weekly status drafts and three RAID snapshots, generated by `pmf report weekly` and `pmf raid` |
| [workspace/reports/dashboard_2026-07-03.html](workspace/reports/dashboard_2026-07-03.html) | The health dashboard for the same date, made by `pmf dashboard`. Open it in a browser; it is a read-only view |
| [workspace/communications/](workspace/communications/) | Notes a person writes from the templates: executive note, retrospective, gate announcement |

## What the walkthrough shows

- All six issue states plus `DEFERRED`: `DETECTED`, `LOGGED`, `TRIAGED`, `DECIDED`, `RESOLVED`, `CLOSED`, and a customer-visible deferral.
- A risk (R-001) that occurs and becomes the Sev 1, linked both ways.
- Change control for the fix: tier Large, two approvers, a filed record, and a budget update the tool insists on.
- A gate (G4) that refuses to pass while the Sev 1 is open, then passes the same command once it is closed.
- Several refusals, each naming the guard that said no. Nothing is written when a command is refused.
- The five health metrics and the worst-of rollup at several dates.

## Run it yourself

The folders above are generated by one script that drives the real `pmf` command line with pinned dates:

```
python3 examples/run_demo.py            # rebuild examples/meridian/workspace and walkthrough
python3 examples/run_demo.py --check    # rebuild in a temp folder and compare; exit 1 if the committed copy is stale
```

The test suite runs the `--check` form, so the example cannot drift from the tool.

To explore the finished workspace with the tool, from the repository root:

```
export PMF_WORKSPACE=examples/meridian/workspace
python3 -m pmf health
python3 -m pmf check
python3 -m pmf show I-007
python3 -m pmf dashboard --out meridian-dashboard.html
```

(On Windows PowerShell use `$env:PMF_WORKSPACE = "examples/meridian/workspace"`.)

## What is and is not generated

Generated by `pmf`: the CSV registers, `events.csv`, the brief draft, the weekly drafts, the RAID snapshots and the dashboard.
Written by a person (the script plays the PM, and says so at each step): decision records, the ECR, the executive note, the retrospective, the gate announcement, and the final edits to the brief. The prompts in [prompts/](../../prompts/) can draft these; the tool never does.
