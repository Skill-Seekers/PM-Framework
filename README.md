# PM-Framework

A guarded program-management workflow for technical programs. Your registers are plain CSV files. A small command-line tool (`pmf`) moves issues, risks, changes and gates through their lifecycles, refuses moves the lifecycle does not allow, and writes every change to an append-only event log. Five skills let an AI assistant draft the paperwork. A read-only HTML dashboard shows the health of the program.

Version 0.1.0. Python 3.8+, standard library only.

> **Read before you use it: [docs/LIMITS.md](docs/LIMITS.md).** In short:
> - The skills have **not** been run in a live assistant session. Test each one on the Meridian example before relying on it.
> - The metrics are a rule-based status aid. They describe the registers; they do not forecast a program.
> - The tool does not detect sensitive data in your registers. Keep each program workspace in a private repository.
> - No tracker connectors, no network calls, no scheduling engine, and nothing is sent, approved or closed automatically.

## What it does

- **Framework.** Ten modules, each answering one question a program manager faces: lifecycle and governance, issue management, RAID vs. issue register, artifacts by stage, communication cadence, communication templates, budget and scope control, program metrics and health, AI-augmented workflow, cross-program coordination. Start with `framework/modules/01_lifecycle_and_governance.md`.
- **Lifecycles that enforce themselves.** Issues, risks, change requests and gates each have explicit states and guards. For example, a waiver or deferral cannot be recorded without a signed decision record, and a gate cannot pass while a blocking issue is open. See [docs/LIFECYCLES.md](docs/LIFECYCLES.md).
- **Two profiles.** `silicon` (nine phases, with a hardware and software/firmware track) and `software` (six phases). Phases, gates, severity model, thresholds and approval tiers live in one profile file per program.
- **Health metrics.** Five metrics, each with a stated rule. The overall status is the worst of the five, never an average.
- **Drafts, not decisions.** The tool and the skills draft briefs, status reports, gate minutes and emails. Nothing is sent, approved or closed on your behalf.
- **A worked example.** `examples/meridian` is a fictional silicon program with a full Sev 1 walkthrough, generated by the real command line.

## Quick start

```
python3 -m pmf init my-program --program "My Program" --profile silicon
cd my-program
python3 -m pmf check
python3 -m pmf health
python3 -m pmf dashboard
```

Then open the dashboard file it reports in a browser. For the full command set and the weekly routine, see [docs/INSTRUCTIONS.md](docs/INSTRUCTIONS.md).

To look at a finished program first, run the worked example from the repository root:

```
export PMF_WORKSPACE=examples/meridian/workspace
python3 -m pmf health
python3 -m pmf check
```

## Repository layout

| Folder | Contents |
|---|---|
| `framework/` | The ten modules and the glossary |
| `profiles/` | `silicon.json`, `software.json` |
| `pmf/` | The `pmf` package (CLI, lifecycles, guards, metrics, dashboard) |
| `templates/` | CSV registers and markdown documents (office versions not yet built) |
| `prompts/` | Ten copy-paste prompts with a mapping to template and lifecycle state |
| `skills/` | Five skills for an AI assistant (setup, log and triage, brief and report, gate review, health check) |
| `examples/meridian/` | Fictional worked example, rebuilt by `examples/run_demo.py` |
| `docs/` | Requirements, scope, assumptions, schemas, lifecycles, instructions, adapting, architecture, limits, build process |
| `tests/` | Unit and consistency tests |
| `tools/` | Repository checkers, privacy scan, plugin packer, generators |

## Status and limits

Read [docs/LIMITS.md](docs/LIMITS.md) before relying on this. In short: the tool is tested, but the skills have not yet been run in a live assistant session, the metrics are a rule-based status aid rather than a forecast, and the framework does not include connectors to any tracker.
