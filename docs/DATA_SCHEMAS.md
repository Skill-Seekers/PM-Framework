# Data schemas

Every register is a plain UTF-8 CSV with a header row. Dates are `YYYY-MM-DD`. Money is a number in the program currency (no symbols). Booleans are `yes` or `no`. Empty means "not known yet", never "zero". Columns marked **computed** are never typed and are never stored; the CLI derives them each run.

A workspace is one folder per program:

```
<program>/
  pmf.config.json        program settings (below)
  issues.csv  risks.csv  assumptions.csv  dependencies.csv
  gates.csv   raci.csv   budget.csv       changes.csv  vendors.csv
  events.csv             append-only audit log
  decisions/DR-001.md    triage and decision records
  briefs/B-001.md        management briefs
  out/                   generated dashboard, reports (safe to delete)
```

## pmf.config.json

| Field | Type | Meaning |
|---|---|---|
| `program` | text | Program name |
| `profile` | text | `silicon`, `software`, or a path to your own profile JSON |
| `baseline_start` | date | Start of the baselined schedule |
| `baseline_end` | date | End of the baselined schedule (last gate's baseline date) |
| `baseline_budget` | number | Total baselined budget |
| `report_date` | date or empty | Date metrics are computed for. Empty = today |
| `currency` | text | Label only, e.g. `USD` |

## issues.csv

| Column | Required at | Notes |
|---|---|---|
| `id` | DETECTED | `I-001`, unique |
| `title` | DETECTED | One line |
| `description` | LOGGED | What broke, where |
| `phase` | LOGGED | Must be a phase id in the profile |
| `owner` | LOGGED | One person. Names containing `/`, `,`, `;`, ` and `, or the word `team` are refused |
| `severity` | LOGGED | A level number from the profile (1 to 4 by default) |
| `detected` | DETECTED | Date. Starts the aging clock |
| `state` | always | One of the issue states in `lifecycles.json` |
| `gate_found` | optional | Gate id where it surfaced |
| `escape_gate` | optional | Gate id that should have caught it, if it escaped an earlier one. Feeds Escape Rate |
| `sched_impact_days` | TRIAGED | Number, from the chosen option once DECIDED |
| `cost_impact` | TRIAGED | Number |
| `decision_ref` | TRIAGED | `DR-001`, a file in `decisions/` |
| `verification_ref` | RESOLVED | Free text pointing to evidence (report name, run id) |
| `brief_ref` | CLOSED (Sev in `brief_required_for`) | `B-001`, a file in `briefs/` |
| `lesson` | CLOSED | One line |
| `exec_notified` | optional | Date the exec notice went out (Sev 1 check) |
| `next_action`, `due` | optional | Free text; date |
| `linked_risk` | optional | Risk id that this issue came from |
| `closed` | CLOSED | Date |
| `escalated` | computed | Open state for more than `escalation.days` |
| `age_days` | computed | Report date (or closed date) minus detected |

## risks.csv

`id` (`R-001`), `title`, `description`, `phase`, `owner`, `probability` (1 to 5), `impact` (1 to 5), `state`, `mitigation`, `next_review` (date), `last_scored` (date), `accepted_by`, `linked_issue`. Computed: `score`, `priority`, `stale`.

## assumptions.csv

`id` (`A-001`), `title`, `description`, `owner`, `status` (`untested`, `validated`, `invalid`), `validate_by` (date), `linked_risk`. An `untested` assumption past `validate_by` is flagged by `pmf check`. An `invalid` one must link a risk or issue.

## dependencies.csv

`id` (`D-001`), `title`, `description`, `owner`, `provider`, `needed_by` (date), `status` (`open`, `at_risk`, `delivered`, `late`), `linked_issue`. A `late` dependency without a linked issue is flagged.

## gates.csv

| Column | Notes |
|---|---|
| `id` | Profile gate id (`G1`) or `X-001` for an issue-triggered gate |
| `name`, `phase` | From the profile for planned gates |
| `type` | `planned` or `issue-triggered` |
| `baseline_date` | Committed date. Never edited after the baseline is approved |
| `planned_date` | Current forecast. Edit this when it slips |
| `actual_date` | Set when the gate reaches GO or CONDITIONAL_GO |
| `state` | PLANNED, REVIEW, GO, CONDITIONAL_GO, NO_GO |
| `criteria_met` | Semicolon list of criterion numbers met (1-based, per profile order) |
| `waiver_refs` | Semicolon list of `DR-` ids covering unmet criteria |
| `triggered_by` | Issue id (issue-triggered gates only) |

## raci.csv

Long form: `phase`, `party`, `role` (`R`, `A`, `C`, `I`), `note`. Generated by `pmf init` from the profile; edit per program. The playbook's reference RACI deliberately has both the customer (accepts) and the PM (owns) as `A` on some rows, so `pmf check` does not enforce a single `A`.

## budget.csv

`phase`, `budget`, `planned_to_date`, `actual_to_date`, `forecast_at_completion`, `updated`. Computed: `variance_pct` = (forecast - budget) / budget, `status` (Amber if forecast > budget, Red if actual > budget).

## changes.csv (ECR log)

`id` (`C-001`), `date`, `title`, `requestor`, `state`, `effort_person_weeks`, `cost_delta`, `schedule_delta_days`, `risk_note`, `decision_ref`, `approvers_signed` (semicolon list), `linked_issue`. Computed: `tier`, `cumulative_cost` (running total of APPROVED and later), `required_approvers`.

## vendors.csv

`vendor`, `committed`, `milestone`, `paid_on_delivery` (`yes`/`no`), `status`. A row with `paid_on_delivery` = `no` is flagged: pay only after acceptance, or price the risk into the contract.

## contention.csv (optional, Module 10)

`resource`, `period` (`YYYY-MM`), `program`, `demand` (person-weeks or units), `capacity`, `owner`, `note`. A simple table for seeing where two programs want the same resource; `pmf check` flags any resource and period where summed demand exceeds capacity. It is not a solver.

## events.csv (append-only)

`ts` (ISO timestamp), `entity` (`issue`, `risk`, `change`, `gate`), `id`, `event` (`transition`, `rescore`, `severity_change`, `edit`), `from_state`, `to_state`, `actor`, `note`, `ref`. Every command that changes a register appends exactly one row. `pmf check` verifies that each register's current state matches the last event for that id.

## decisions/DR-NNN.md

A markdown file with this exact skeleton (the CLI reads it):

```
# DR-001: <issue title>
Issue: I-001
Date: 2026-10-26
Customer visible: yes|no

## Options
| Option | Description | Schedule (days) | Cost | Risk |
|---|---|---|---|---|
| A | Fix now | +3 | 12000 | Low |
| B | Waive with conditions | 0 | 0 | Medium |
| C | Defer to next revision | 0 | 0 | High |

Recommendation: A - one-line rationale

## Decision
Chosen: A
Decided by: <name>
Decided on: 2026-10-27
Signed: yes|no
Customer acceptance: <ref or n/a>
```

TRIAGED requires the Options table (all three rows, with schedule and cost) and a Recommendation line. DECIDED requires `Chosen`, `Decided by`, `Decided on`, and `Signed: yes` when the choice is B or C.

## briefs/B-NNN.md

Sections `WHAT`, `IMPACT`, `OPTIONS`, `RECOMMENDATION`, `DECISION NEEDED BY`, each non-empty. Generated as a draft from the register and the decision record by `pmf brief`; the PM edits it.

## Profile fields

See `profiles/silicon.json`; each key is commented by its `_doc` entries and explained in [ADAPTING.md](ADAPTING.md). The lifecycles (states, transitions, guards) are not per-profile: they live in `pmf/data/lifecycles.json` and are the same for every program.

## Metric definitions

All five use the report date and the profile's thresholds. Workstream status is the worst of the five colors; program status is the worst of all workstreams (a single-workstream program has one).

1. **Schedule Variance.** `SV days` = forecast minus baseline of the last gate, where forecast is the actual date if the gate is done, else its `planned_date`. `SV %` = SV days / (`baseline_end` - `baseline_start`). Green within `green_max_pct` behind baseline; Amber up to `amber_max_pct` behind; Red beyond, or when any planned gate is overdue (not done and `planned_date` earlier than the report date). Being ahead of baseline is Green.
2. **Gate On-Time Rate.** Completed planned gates with `actual_date` <= `baseline_date`, divided by completed planned gates. No completed gate = not rated (grey), never Green by default.
3. **Issue Aging.** "Open" means the issue is in one of the profile's `escalation.open_states_issue` (shipped: DETECTED, LOGGED, TRIAGED, DECIDED); RESOLVED, DEFERRED and CLOSED are not open. For each open issue of a severity that has `aging_days` (shipped: Sev 1 and Sev 2), age = report date - detected. Green at or under `green_max`, Amber up to `amber_max`, Red beyond. The metric color is the worst open issue; the report shows the count past each threshold. An empty `issues.csv` is not rated: an empty register cannot be told apart from an unmaintained one.
4. **Escape Rate.** Issues whose `escape_gate` is set, divided by all issues, per phase and overall. A phase with fewer than `min_issues_for_rating` issues is not rated. Green is strictly under `green_max_pct` (10% is Amber), Amber up to and including `amber_max_pct` (20%), Red above. The metric color is the worst rated phase. (The minimum is a build default, not in Module 08.)
5. **Budget Burn Ratio.** `sum(actual_to_date)` / `sum(planned_to_date)`. Green 0.9 to 1.1; Amber 1.1 to 1.25 or below 0.9 (under-spend can mean under-resourced; Module 08 leaves 0.75 to 0.9 undefined and this is the build default); Red above 1.25, or when `sum(forecast_at_completion)` exceeds `baseline_budget`.

Unrated metrics (no data) show grey with the reason and do not drag the rollup down, but they are never counted as Green and the rollup reason names them; a rollup that is all grey says "not enough data".
