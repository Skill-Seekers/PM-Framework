# Build process

How this release was built, checked and prepared. Written so that a later maintainer can repeat each step and see what was and was not verified.

## Stages

| Stage | What was done | Output |
|---|---|---|
| S0 Intake | Inventoried every source document in the internal playbook (keep, rewrite, port, or drop). Built a private denylist of names, employers, identifiers and metrics that must not ship. | Source inventory, kept outside the repository |
| S1 Spec | Wrote requirements, assumptions, scope, data schemas and the lifecycle definitions. Defined the two profiles. | `docs/REQUIREMENTS.md`, `ASSUMPTIONS.md`, `SCOPE.md`, `DATA_SCHEMAS.md`, `LIFECYCLES.md`, `profiles/` |
| S2 Content | Ported and rewrote the ten modules and the glossary; removed career-specific framing and employer references; rebuilt the prompts and document templates. | `framework/`, `prompts/`, `templates/` |
| S3 Engine | Built the `pmf` package: profile loader, lifecycle and guard enforcement, metrics, register checks, dashboard, reports. | `pmf/`, `tests/` |
| S4 Example | Built the fictional Meridian program and a Sev 1 walkthrough, generated by the real command line. | `examples/meridian/`, `examples/run_demo.py` |
| S5 Dashboards | Built the read-only dashboard and the lifecycle diagrams, with no external requests. Checked by structure tests. | `pmf/dashboard.py`, `docs/diagrams/`, `docs/explainer.html` |
| S6 Skills | Wrote the five skills against the command line. | `skills/`, `.claude-plugin/` |
| S7 Documentation | Wrote the root documents and the guides in `docs/`. | `README.md`, `CHANGELOG.md`, `CONTRIBUTING.md`, `LICENSE` (MIT), `docs/INSTRUCTIONS.md`, `ADAPTING.md`, `ARCHITECTURE.md`, `LIMITS.md`, `BUILD_PROCESS.md` |
| S8 Privacy gate | Self-test of the scanner, scan of the release tree against the private denylist, test suite, checkers, and a manifest for human review. | Scan report and manifest, kept outside the repository |

## Checks run for 0.1.0

Run from the repository root, in this order:

```
python3 tools/privacy_scan.py selftest
python3 tools/privacy_scan.py scan . --denylist <private denylist, outside the repo>
python3 -m unittest discover -s tests
python3 tools/check_spec.py
python3 tools/check_content.py
python3 tools/check_links.py --allow-missing "docs/ADAPTING.md,docs/LIMITS.md,README.md,examples/meridian"
python3 examples/run_demo.py --check
python3 tools/gen_lifecycles.py --check
python3 tools/gen_templates.py --check
python3 tools/privacy_scan.py manifest . --out <manifest, outside the repo>
```

The `--allow-missing` list on the link check is for documents that exist in the release but link to each other through relative paths; remove it once every linked file is present, which at 0.1.0 they all are.

## Release steps

1. Run every check above. Any failure stops the release.
2. Read the manifest by eye: every file, its size and its hash. Confirm there are no unexpected files and no images or PDFs without a reason.
3. Open the Meridian dashboard in a browser and check it.
4. Confirm `LICENSE` is MIT and the copyright line names the holder you want.
5. Copy the release tree into the repository clone (without `.git`), commit, and push.
6. Keep the denylist and the scan report outside the repository. Never commit them.

## Known gaps at 0.1.0

See [LIMITS.md](LIMITS.md). In summary: the skills have not been run live; office versions are not built; the Windows test run is outstanding.
